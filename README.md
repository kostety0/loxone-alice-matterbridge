# Loxone → Алиса через Matter (локально, без облаков)

Как подключить Loxone Miniserver (в том числе **Gen 1**) к умному дому Яндекса, чтобы Алиса
управляла светом **по локальной сети**: без сторонних облачных сервисов, белого IP и туннелей.

```
Яндекс Станция (Matter-хаб) ──Matter, локальная сеть──► Matterbridge (ПК с Windows) ──websocket──► Loxone Miniserver
```

Под капотом [Matterbridge](https://github.com/Luligu/matterbridge) с плагином
[matterbridge-loxone](https://www.npmjs.com/package/matterbridge-loxone). Мост показывает
устройства Loxone как Matter-устройства, а Станция подключает их как обычные Matter-лампы.

## Что нужно

- **Яндекс Станция с Matter-хабом.** Проверено на Станции Миди. Matter поддерживают Станция 2,
  Миди, Мини, Лайт и Хаб Яндекса.
- **Постоянно включённый ПК с Windows 10/11** в той же сети, что и Станция. Подойдёт мини-ПК,
  в том числе подключённый по кабелю, без Wi-Fi.
- **Loxone Miniserver** и доступ к Loxone Config.

Требования к сети:
- ПК и Станция в **одной подсети** (не гостевой);
- на роутере **не включены изоляция клиентов (AP isolation)** и блокировка multicast между Wi-Fi и LAN;
- на ПК включён IPv6 (по умолчанию включён).

## Установка

Все команды выполняются в **PowerShell от имени администратора**: Пуск → «PowerShell» →
правой кнопкой → «Запуск от имени администратора». Скачайте репозиторий (Code → Download ZIP),
распакуйте его и перейдите в папку `scripts`:

```powershell
cd C:\путь\к\loxone-alice-matterbridge\scripts
```

> Скрипты `.ps1` запускайте через `powershell -ExecutionPolicy Bypass -File ...`. Без этого
> Windows выдаст ошибку «выполнение сценариев отключено в этой системе».

### Шаг 0. Пользователь в Loxone Config

1. Создайте отдельного пользователя, например `alice`. Пароль лучше составить из латиницы и цифр.
2. **Выдайте ему права на нужные функциональные блоки**: свет, выключатели, жалюзи. Без
   прав плагин подключится, но увидит `Found 0 controls`.
3. Нажмите «Сохранить в Miniserver».
4. Запишите IP и **порт** веб-интерфейса Miniserver'а. Порт не всегда 80: проверьте, по какому
   адресу открывается `http://IP:порт`.

### Шаг 1. Node.js и Matterbridge

Дважды щёлкните `Install.bat` (сам попросит права администратора) или выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\1-install.ps1
```

Скрипт делает следующее:
- ставит Node.js LTS прямо с nodejs.org (winget не нужен, его нет на LTSC и старых сборках);
- ставит Matterbridge;
- разрешает Node.js в брандмауэре;
- переводит сеть в профиль «Частная»;
- отключает Teredo (виртуальный интерфейс, из-за которого Matter может объявлять себя не туда);
- отключает сон при работе от сети.

### Шаг 2. Автозапуск в фоне

```powershell
powershell -ExecutionPolicy Bypass -File .\2-autostart.ps1 -LoxoneHost 192.168.1.77
```

Скрипт создаёт задачу в Планировщике заданий. После этого Matterbridge:
- запускается **при включении ПК, даже без входа в Windows**, в фоне и без окна;
- сам перезапускается, если упал или если нажали **Restart** в веб-интерфейсе;
- работает **строго в одном экземпляре**;
- объявляет себя для Matter только через сетевой адаптер в подсети Miniserver'а (`-mdnsinterface`).
  Адаптер можно задать и явно: `-Interface "Ethernet"`.

Через 20–30 секунд откройте веб-интерфейс по адресу `http://IP-этого-ПК:8283`.

### Шаг 3. Плагин Loxone

1. В веб-интерфейсе, в поле **Install plugins**, введите `matterbridge-loxone` и нажмите **Install**.
   Сообщение об ошибке плагина до настройки — это нормально.
2. Настройте плагин и соберите список устройств:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\3-configure-loxone.ps1 -LoxoneHost 192.168.1.77 -Port 80 -User alice
   ```
   Скрипт спросит пароль скрытым вводом и нигде его не выводит. Затем он сам:
   - останавливает Matterbridge (иначе тот перезапишет конфиг при выходе);
   - получает с Miniserver'а список устройств и строит `uuidsandtypes`: Switch → `light`,
     выходы Lighting Controller → `lightoutput`, Jalousie → `shade`;
   - записывает конфиг **в UTF-8 без BOM** и запускает Matterbridge.
3. Проверьте вкладку **Devices**: там должны быть ваши устройства. Попробуйте включить одно прямо
   из веб-интерфейса.

### Шаг 4. Подключение к Алисе

1. «Дом с Алисой» → **+** → **Устройство умного дома** → **Поиск Matter**.
2. Выберите Станцию как хаб.
3. Отсканируйте QR-код с главной страницы Matterbridge. Если не сканируется, введите цифровой код.
4. Распределите устройства по комнатам: «Алиса, включи свет на кухне».

Чтобы проверить, что управление действительно локальное, отключите на роутере интернет (WAN)
и попросите Алису включить свет.

## Обслуживание

| Действие | Команда (PowerShell от администратора) |
|---|---|
| Остановить | `powershell -ExecutionPolicy Bypass -File .\stop.ps1` |
| Запустить | `Start-ScheduledTask -TaskName Matterbridge` |
| Журнал | веб-интерфейс → вкладка **Logs** |
| Добавили устройства в Loxone | выдайте права пользователю и снова запустите `3-configure-loxone.ps1` |

Файлы на ПК:
- `%USERPROFILE%\.matterbridge\matterbridge-loxone.config.json`: настройки плагина;
- `%USERPROFILE%\.matterbridge\`: данные Matterbridge и сопряжение Matter. **Не удаляйте**, иначе
  придётся заново добавлять устройства в Алису;
- `%APPDATA%\npm\node_modules\`: сам Matterbridge и плагин.

**Правило:** конфиг плагина можно править вручную только при **остановленном** Matterbridge,
и сохранять его нужно **в UTF-8 без BOM**. Блокнот в Windows 10 1903 и новее по умолчанию
сохраняет именно так.

## Проблемы и решения

| Симптом в журнале / на экране | Причина | Что делать |
|---|---|---|
| `выполнение сценариев отключено в этой системе` | ExecutionPolicy | Запускать через `powershell -ExecutionPolicy Bypass -File ...` |
| `winget не распознано` | В системе нет winget | `1-install.ps1` качает Node.js напрямую, winget не нужен |
| `Server offline` в веб-интерфейсе | Процесс Matterbridge не запущен | `Start-ScheduledTask -TaskName Matterbridge` |
| `Connect Timeout Error (attempted address: ...)` | Неверный IP или порт Miniserver'а | Проверить `http://IP:порт` в браузере и перезапустить `3-configure-loxone.ps1` |
| `Found 0 controls` | У пользователя нет прав на блоки | Выдать права в Loxone Config и сохранить в Miniserver |
| `uuidsandtypes is not iterable` | Список устройств пуст или записан не массивом | Перезапустить `3-configure-loxone.ps1` |
| `Unexpected token '﻿' ... is not valid JSON` | Конфиг сохранён с BOM (например, `Set-Content -Encoding UTF8` в PowerShell 5.1) | Перезапустить `3-configure-loxone.ps1` |
| `Loxone host is not set` | Конфиг не прочитался (обычно из-за BOM) | См. строку выше |
| `IP ... temporarily blocked, too many failed login attempts` | Неверный пароль и/или две копии Matterbridge | `stop.ps1` → проверить пароль с другого устройства → подождать 10–15 минут → `3-configure-loxone.ps1` |
| Изменения в конфиге «пропадают» | Конфиг правили при запущенном Matterbridge | Сначала `stop.ps1`, потом правка |
| `Found network interface 'Teredo Tunneling Pseudo-Interface'` | Виртуальный интерфейс Teredo | `1-install.ps1` его отключает; задать `-mdnsinterface` (делает `2-autostart.ps1`) |
| Станция не находит мост | Разные подсети, гостевая сеть, AP isolation | См. «Требования к сети» |
| Кракозябры в выводе PowerShell | PowerShell 5.1 неверно декодировал UTF-8 при печати | На работу не влияет; скрипты декодируют сами |

## Альтернатива: свой облачный навык

В папке [`alternative-yandex-skill`](alternative-yandex-skill/) лежит приватный навык умного
дома для Яндекс Диалогов на Python. Он управляет Miniserver'ом по HTTP API и подходит, если
Matter недоступен. Минусы: нужен HTTPS-туннель или белый IP, а Алиса работает через облако
Яндекса. Подробности в его README.

## Безопасность

- В репозитории **нет паролей, токенов и адресов** конкретной установки, все значения в
  примерах условные.
- Пароль Loxone хранится только локально, в `%USERPROFILE%\.matterbridge\`, на вашем ПК.
- Для моста используйте **отдельного пользователя Loxone** с правами только на нужные блоки.
- Веб-интерфейс Matterbridge (порт 8283) открыт только в частной сети. Пароль на него можно
  задать в **Settings**.
